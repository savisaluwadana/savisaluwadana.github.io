CASE 01
Go / Wails / SQLite Public repo

Advance HRIS

How do you sync an offline edit?

Advance HRIS skips incoming employee records that still have a pending local edit. A sync can refresh other records while that edit waits for resolution.

Next.js Web + Wails / React Desktop → Go API → PostgreSQL

Trade-off: Offline operation adds synchronization, conflict resolution and local-data protection concerns.

CASE 02
Next.js / PostgreSQL Public repo

FreshPick / FreshOnTime

How do you schedule a repeat delivery?

FreshPick tracks recurring grocery orders separately from payment collection. A shopper can schedule another delivery and pay cash when it arrives.

Next.js → Prisma / PostgreSQL → recurring delivery + media storage

Trade-off: One app keeps order transitions together; background jobs and integrations need separate scheduling.

CASE 03
Go / PostgreSQL / MCP Public repo

Property Management OS

Who authorizes an agent’s request?

Property Management OS routes MCP tool calls through the same authenticated Go API as the web app. The API owns the permission check and the database write.

Next.js → Go modular monolith → PostgreSQL → Outbox worker → MCP

Trade-off: Transactional domain authority stays in one backend, but asynchronous delivery needs worker and retry handling.

PRINCIPLE 01

Boundaries before microservices

Start with a modular monolith where domain ownership is explicit and transactions stay honest. Extract services only when operational isolation earns the network cost.

PRINCIPLE 02

One authenticated authority path

Web UIs, desktop sync queues, and MCP agent tools should all speak through the same application API so permissions, tenant scope, and audit logs live in one place.

PRINCIPLE 03

Document scope & unfinished edges clearly

A credible engineering portfolio distinguishes implemented code from prototypes, states deployment prerequisites, and links directly to verifiable source repositories.
