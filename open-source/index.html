How to inspect the work

For a project, I start with the source code index and the linked README. Each product detail page points to its architecture, local setup, main design decision, trade-off and current limitations.

A public repository is not necessarily open-source licensed. Check the licence before copying or redistributing code. The source index distinguishes MIT, proprietary and unspecified terms.

Start with the engineering boundaries

The agentic systems walkthroughs trace requests through tools, APIs, recorded state and human review. The architecture reference compares local-first workflows, tenant isolation and payment boundaries across products.

These references help identify the service and rule affected by a change. Product diagrams and source links provide the next level of detail; they do not replace checking the current repository.

Discuss code or documentation work

For a specific change, start with the repository's README and issue tracker. You can also contact me with the relevant repository and a reproducible problem.
